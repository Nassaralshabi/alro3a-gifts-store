# تقرير اختبار الأداء على شبكة ضعيفة

## نطاق الاختبار

استهدف الاختبار الصفحة الرئيسية، صفحة المتجر، ومسار تفاصيل المنتج `graduation-photo-board`. تم فحص العرض المكتبي وعرض الهاتف 390×844، ثم تنفيذ مقارنة موحدة لطلبات API باستخدام `curl` مع تقييد سرعة النقل إلى 16 كيلوبت/ثانية. المقارنة قبل/بعد تعزل التغييرين الرئيسيين: قائمة الكتالوج الكامل مقابل قائمة المنتجات المميزة المحدودة، ودفعة صفحة المنتج القديمة التي تتضمن `homeContent` مقابل الدفعة الجديدة التي لا تتضمنه.

هذا اختبار نقل واستجابة للطلبات على خادم التطوير، وليس قياسًا ميدانيًا كاملًا على جهاز مستخدم. أزمنة الخادم المحلي قد تتأثر بالتخزين المؤقت وبدء العملية، لذلك يُستخدم حجم النقل وعدد الطلبات كمؤشرين أقوى من زمن عينة واحدة.

## التغييرات المطبقة

| المسار | التغيير | الأثر المتوقع |
|---|---|---|
| الصفحة الرئيسية | طلب `featuredOnly: true` مع `limit: 8` من قاعدة البيانات، بدل جلب الكتالوج كاملًا ثم قصّه في العميل | تقليل حجم JSON والعمل على العميل |
| الصفحة الرئيسية | الحفاظ على أبعاد الصور، تحميل صورة البطل بأولوية عالية، وتأجيل صورة العرض الثانوية | تقليل القفز البصري وتأجيل النقل غير الحرج |
| بطاقات المنتجات | `loading="lazy"` و`decoding="async"` و`fetchPriority="low"` مع أبعاد ثابتة و`content-visibility: auto` | تقليل تكلفة الصور والعمل خارج نطاق العرض |
| تفاصيل المنتج | هيكل تحميل يحافظ على أبعاد الصفحة بدل مؤشر انتظار عام | استجابة مدركة أفضل أثناء انتظار API |
| تفاصيل المنتج والمتجر | إزالة استعلام `homeContent` من الغلاف العام وتمرير الشعار من الصفحة الرئيسية فقط | صفحة المنتج أصبحت تطلب `contact` و`productBySlug` بدل `contact` و`homeContent` و`productBySlug` |
| حالات الفشل | إضافة رسائل خطأ وزر إعادة محاولة للمنتجات وتفاصيل المنتج، مع فصل الخطأ الشبكي عن المنتج غير الموجود | استعادة أوضح دون إعادة تحميل الصفحة |

## قياس موحد قبل/بعد

نفّذت القياسات من الجهاز نفسه وعلى خادم التطوير نفسه وبأمر `curl` نفسه مع `--limit-rate 16k`. يشمل القياس الكامل HTML الأساسي للمسار، بينما تقيس المقارنة التفصيلية طلبات API الحرجة التي تغيّرت فعليًا. لم يتغير `index.html` أو HTML الغلاف بين النسختين، لذلك لا ننسب أي تحسن إلى HTML؛ الفرق المقصود يقع في API، الصور، وتقسيم التحميل داخل التطبيق.

### المسار الكامل

| المسار | حالة HTML | HTTP | الحجم | الزمن الكلي |
|---|---|---:|---:|---:|
| `/` | بعد التحسين؛ HTML الغلاف نفسه قبل التحسين | 200 | 368,408 بايت | 22.204 ثانية |
| `/products/graduation-photo-board` | بعد التحسين؛ HTML الغلاف نفسه قبل التحسين | 200 | 368,408 بايت | 22.204 ثانية |

تساوي HTML للمسارين متوقع في تطبيق SPA، ولا يعني أن زمن التجربة المرئية متساوٍ؛ بعد وصول الحزمة يبدأ كل مسار طلبات API مختلفة، وتحميل الصور، وتصيير مكونات مختلفة. لم يكن baseline تاريخي كامل للـ HTML والأصول مسجلًا قبل بدء هذه الجلسة، لذلك نعرض هنا القياس الحالي للمسار الكامل بصدق، ونفصل عنه المقارنة قبل/بعد للطلبات التي تغيّرت فعليًا.

### الأصول الحرجة

| الأصل | الحالة الحالية تحت `--limit-rate 16k` | الحجم |
|---|---:|---:|
| JavaScript الرئيسي بعد build | ملف `index-BFknU0uu.js` | 714,658 بايت |
| CSS الرئيسي بعد build | ملف `index-BjX43NrA.css` | 130,339 بايت |
| صورة البطل بعد اتباع redirect التخزين | HTTP 200 | 12,643 بايت |
| صورة fallback المستخدمة في تفاصيل المنتج | HTTP 200 | 12,643 بايت |

الصور خارج نطاق العرض في البطاقات تستخدم lazy loading، بينما صورة البطل وصورة تفاصيل المنتج لهما أبعاد ثابتة وأولوية مناسبة. هذا الفصل يوضح أن HTML وحده لا يمثل تكلفة المسار الكاملة.

### الطلبات الحرجة قبل/بعد

في حالة الصفحة الرئيسية، يمثل «قبل» استعلام المنتجات الكامل المستخدم سابقًا، ويمثل «بعد» استعلام المنتجات المميزة المحدود المستخدم حاليًا. في حالة صفحة المنتج، يمثل «قبل» دفعة `contact + homeContent + productBySlug`، ويمثل «بعد» دفعة `contact + productBySlug`.

| المسار والطلب | الحالة | HTTP | الحجم | الزمن الكلي |
|---|---|---:|---:|---:|
| منتجات الصفحة الرئيسية، الكتالوج الكامل | قبل | 200 | 24,194 بايت | 0.047710 ثانية |
| منتجات الصفحة الرئيسية، 8 منتجات مميزة | بعد | 200 | 6,420 بايت | 0.040949 ثانية |
| دفعة تفاصيل المنتج مع `homeContent` | قبل | 200 | 1,430 بايت | 0.064423 ثانية |
| دفعة تفاصيل المنتج دون `homeContent` | بعد | 200 | 1,171 بايت | 0.039825 ثانية |

ينخفض حجم استجابة قائمة الصفحة الرئيسية بنحو **73.5%**، وينخفض حجم دفعة تفاصيل المنتج بنحو **18.1%**. تحسن زمن العينة المحلية بنحو 14.2% لقائمة الصفحة الرئيسية وبنحو 38.2% لدفعة تفاصيل المنتج، لكن هذه النسب الزمنية لا تُعمّم على الإنتاج بسبب تذبذب الخادم والتخزين المؤقت؛ أما خفض الحجم وإزالة الطلب فهي فروقات مباشرة قابلة للتحقق.

## قياسات النقل الإضافية

| القياس | ظروف الاختبار | النتيجة الحالية |
|---|---|---:|
| HTML الصفحة الرئيسية | `curl --limit-rate 64k` | HTTP 200، حجم 368,408 بايت، 4.998 ثانية |
| طلب المنتجات المميزة | `curl --limit-rate 16k`، `featuredOnly=true`, `limit=8` | HTTP 200، حجم 6,420 بايت، 0.069 ثانية في عينة منفصلة |
| طلب تفاصيل المنتج المفرد | `curl --limit-rate 16k` | HTTP 200، حجم 916 بايت، 0.040 ثانية في عينة منفصلة |

تتضمن استجابة HTML حزمة التطبيق الأولية، ولذلك تكون أبطأ بكثير من API عند تقييد النقل. الصور تُحمّل لاحقًا وفق `loading` وأولوية الطلب، لذا لا يُفترض أن يساوي زمن HTML زمن اكتمال الصفحة المرئية.

## التحقق الوظيفي

نجح `pnpm check`، ونجحت اختبارات Vitest الأربعة بإجمالي 14 اختباراً، كما نجح `pnpm build`. أظهرت اللقطات المكتبية والهاتفية أن الصفحة الرئيسية والمتجر وتفاصيل المنتج بقيت قابلة للاستخدام، وأن الصور والبطاقات تحافظ على أبعادها أثناء التحميل. تمت إضافة حالة خطأ وإعادة محاولة للمنتجات في الصفحة الرئيسية والكتالوج، مع إبقاء حالة «المنتج غير موجود» مستقلة عنها.

بعد تحديث صفحة الكتالوج الخفيفة، نجح `pnpm check` و15 اختبار Vitest. يحاكي اختبار وحدة فشل `productsPage` المؤقت ويتحقق من وصول الخطأ إلى طبقة الواجهة التي تعرض رسالة واضحة وزر إعادة المحاولة. تظهر الواجهات هياكل تحميل ثابتة للبطاقات والصورة الرئيسية قبل اكتمال البيانات، لذلك لا يتغير موضع المحتوى عند بطء الطلب.

## القيود والخطوة التالية

حجم حزمة JavaScript الحالية في build هو نحو 735.72 كيلوبايت قبل الضغط و209.06 كيلوبايت مضغوطاً، مع استمرار وجود تحذير من chunk رئيسي أكبر من 500 كيلوبايت. يتضمن HTML الأولي أيضاً وقت تشغيل المنصة المضمن، لذلك لا يُنصح بتغييره مباشرةً من كود المتجر. يبقى تحليل الاعتمادات المشتركة في الحزمة الرئيسية مرشحاً لتحسين مستقل عند توفر تحكم أكبر بوقت تشغيل المنصة.

تم أيضاً تأجيل كود سلة الطلب حتى يفتحها المستخدم، بدلاً من تضمينها في كل مسار للمتجر، كما مُددت مدة صلاحية بيانات الكتالوج العامة إلى عشر دقائق مع إبقاء عمر الذاكرة ثلاثين دقيقة وإيقاف إعادة الجلب عند عودة التركيز. لا ينطبق هذا التخزين المؤقت على إنشاء الطلبات أو أي إجراء معاملاتي.

أنتج بناء الإنتاج بعد هذا التأجيل ملفاً مستقلاً لسلة الطلب بحجم **20.54 كيلوبايت** مصغراً (**3.91 كيلوبايت** مضغوطاً). انخفضت الحزمة الرئيسية من 735.72 إلى **712.17 كيلوبايت** مصغرة، ومن 209.06 إلى **205.38 كيلوبايت** مضغوطة؛ أي خفض مقداره **3.20%** و**1.76%** على الترتيب. يبقى تحذير الكتلة الرئيسية موثقاً كقيد متعلق بوقت تشغيل المنصة والاعتمادات المشتركة.
